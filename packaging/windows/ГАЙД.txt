============================================
 QUIVER — портабельна версія (Windows)
============================================

Це переносний чат Twitch для накладання в OBS. Усю папку можна
скопіювати куди завгодно (флешка, інший ПК) — працюватиме, бо всі шляхи
всередині відносні.

Це ШАБЛОН: канал і Twitch-ключі порожні. Заповни їх під себе (див. нижче).

Що лежить у папці
------------------------------------------------------------
  quiver-chat.exe          сам сервіс (програма)
  widget\                  файли віджета (HTML/JS/CSS) — не чіпати
  chat.ron                 головний конфіг: канал, шрифт, емоти, CSS
  credentials.ron          ТВОЇ Twitch-ключі (створити з .example, див. нижче)
  credentials.ron.example  приклад файлу ключів
  css\                     папка зі стилями:
    custom-widget.css        стиль за замовчуванням — редагуй тут
    likh_tar.css             друга готова тема (пухирці) — див. розділ 6
  badges\                  папка для твоїх кастомних бейджів (розділ 8)
  start-quiver.bat         ручний запуск (подвійний клік)
  stop-quiver.bat          зупинка
  auth-quiver.bat          авторизація Twitch (повний доступ до подій) — розділ 5
  quiver-obs-autostart.lua автозапуск разом з OBS
  ГАЙД.txt                 цей файл

------------------------------------------------------------
 1. НАЛАШТУВАННЯ (один раз)
------------------------------------------------------------
  а) Канал. Відкрий chat.ron у Блокноті, знайди рядок

         channel: "CHANGE_ME",

     і замість CHANGE_ME впиши ім'я свого каналу маленькими літерами,
     напр.  channel: "mysuperchannel",

  б) Ключі Twitch (щоб були бейджі та емоти каналу):
     - Скопіюй файл  credentials.ron.example  і переіменуй копію в
       credentials.ron  (саме без ".example").
     - Відкрий credentials.ron у Блокноті, впиши свої client_id і
       client_secret (як отримати — написано в самому файлі).
     - Якщо ключів немає — не страшно: чат працюватиме, але без бейджів
       та емотів каналу.

------------------------------------------------------------
 2. ЗАПУСК
------------------------------------------------------------
  Варіант А — руками:
     Двічі клікни  start-quiver.bat

  Варіант Б — автоматично разом з OBS:
     У OBS:  Tools -> Scripts  -> "+"  -> вибери  quiver-obs-autostart.lua
     Тепер сервер піднімається щоразу, коли відкривається OBS.

  Перевірка: відкрий у браузері  http://127.0.0.1:4783/health
             має бути  200 ok
  Сам чат:   http://127.0.0.1:4783

------------------------------------------------------------
 3. ДОДАЄМО В OBS (один раз)
------------------------------------------------------------
  Джерела -> "+" -> Браузер:
     URL:          http://127.0.0.1:4783
     Ширина/Висота: під місце на сцені (напр. 480 x 720)
     Увімкни "Оновлювати браузер, коли сцена стає активною".

------------------------------------------------------------
 4. ЗУПИНКА
------------------------------------------------------------
  Двічі клікни  stop-quiver.bat
  (або:  taskkill /F /IM quiver-chat.exe)
  Якщо додав Lua-скрипт і позначив "Зупиняти сервер при закритті OBS",
  сервер зупиниться сам разом з OBS.

------------------------------------------------------------
 5. ПОВНИЙ ДОСТУП ДО ПОДІЙ (oauth.json)
------------------------------------------------------------
  Що це дає:
     Звичайний чат (текст, бейджі, емоти) працює й без цього кроку.
     Але щоб бачити ПОДІЇ каналу — нагороди за бали (навіть без тексту
     в повідомленні), підписки/гіфт-саби, рейди, хайпотяги, предикти,
     опитування, бітси — потрібен токен доступу каналу. Він зберігається
     у файлі  oauth.json.

  Як зробити (один раз):
     - Переконайся, що крок 1(б) зроблено (є credentials.ron).
     - Двічі клікни  auth-quiver.bat.
     - Відкриється браузер (або зайди на https://www.twitch.tv/activate),
       введи код, який показано у вікні, і підтверди доступ.
     - Коли з'явиться рядок  "Stored at: ..."  — готово. Вікно можна
       закрити, oauth.json збережено. Сервер підхопить його сам.

  Куди зберігається:
     У підпапку  quiver\oauth.json  ПОРУЧ з програмою (усередині папки
     Quiver_windows). Це твій особистий токен — нікому його не передавай.

  Перевірити, що токен на місці:
     quiver-chat.exe --config chat.ron --auth-print
     Покаже JSON зі шляхом до токена і списком дозволів.

  Передати іншій людині (щоб і в неї був повний доступ):
     Не копіюй свій oauth.json — це твої дані. Нехай вона створить свій
     credentials.ron і один раз запустить auth-quiver.bat під своїм
     Twitch-акаунтом (бажано — акаунтом самого каналу).

 6. СТИЛЬ (дві теми)
------------------------------------------------------------
  Тема = файл CSS, який підключається рядком у chat.ron:

     custom_css: Some(( uri: "file://css/custom-widget.css" )),

  Файлів дві, обидва в папці css\:
     - css\custom-widget.css — простий стиль за замовчуванням. Міняй тут
       кольори/розміри, усе перекоменковано з прикладами.
     - css\likh_tar.css      — готова тема «пухирці»: повідомлення-картки з
       іменем-шапкою і підсвіткою ролей.

  Щоб перемкнутися на likh_tar.css:
     1) у chat.ron змініть рядок вище на
            custom_css: Some(( uri: "file://css/likh_tar.css" )),
     2) ця тема бере колір рамки зі змінної --message-border-color, яку
        виставляє блок role_css. Додай його всередину theme: (...) —
        у прикладі нижче. Без нього всі бульки будуть одного кольору.

        role_css: Some({
            "subscriber":    "div.msg.role-subscriber { --message-border-color: #ffd700 !important; }",
            "founder":       "div.msg.role-founder { --message-border-color: #ffd700 !important; }",
            "vip":           "div.msg.role-vip { --message-border-color: #e040fb !important; }",
            "moderator":     "div.msg.role-moderator { --message-border-color: #00ff7f !important; }",
            "broadcaster":   "div.msg.role-broadcaster { --message-border-color: #ff4500 !important; }",
            "lead_moderator":"div.msg.role-lead_moderator { --message-border-color: #8b4513 !important; }",
            "global_mod":    "div.msg.role-global_mod { --message-border-color: #8b4513 !important; }",
        }),

     Поради:
       - значення role_css — ЦІЛЕ правило з селектором (як вище), а не
         просто "колір: значення"; інакше буде попередження і правило
         не застосується.
       - щоб перебити вбудований стиль, додавай !important.

  Зміну CSS видно НАЖИВО: достатньо зберегти файл (див. ПРИМІТКИ).

  ── БАНЕРИ ПОДІЙ: рідімки та бітси ──
  У chat.ron, всередині theme: (...), є блок event_layout — як малювати
  банери нагород за бали (redeem) і бітсів (cheer). Дефолт уже стоїть:

     event_layout: (
         redeem: "{reward_icon} {user} redeemed {reward}{input_clause}",
         cheer:  "{bits_icon} {user} cheered {bits} bits{message_clause}",
         event_name: true,
     ),

  Що це дає: у банері буде іконка нагороди/бітсів, хто, назва нагороди і
  (якщо є) текст вводу/повідомлення. Щоб змінити вигляд — ЗАМІНИ рядок
  (не додавай другий однойменний ключ: RON впаде на дублікаті). Напр.
  українською:

     redeem: "{user} {points_icon}рідімить {reward_icon} {reward}{input_clause}",
     cheer:  "{bits_icon} {user} заряджає {bits} бітсів{message_clause}",

  Токени (усе інше — помилка конфіга, релоад відхилять):
     redeem: {user} хто, {reward} назва нагороди,
             {reward_icon} іконка нагороди, {points_icon} іконка балів,
             {input} текст вводу, {input_clause} = ": <ввід>"/""
     cheer:  {user} хто, {bits} сума, {bits_icon} бейдж бітсів,
             {message} текст, {message_clause} = ": <текст>"/""
     event_name: true|false — показувати пігулку назви події (лише
                 redeem/cheer; інші види не зачіпає).

  УВАГА: іконку самої нагороди для рідімів дає Twitch (потрібен зв'язок по
     API — див. розділ 5). Без oauth/ключів банер все одно буде, просто
     без іконки.

 7. ФІЛЬТРИ (приклади правил)
------------------------------------------------------------
  Секція filters: у chat.ron. Кожен вимір — окремо, зі своїм режимом:

     content: Some((
         mode: allowlist,        // показувати ЛИШЕ те, що збігається
         items: [ "патерн1", "патерн2" ],
     )),
     // або
     role: Some((
         mode: denylist,         // ховати все, що збігається
         items: [ "subscriber" ],
     )),

  РЕЖИМИ:
     allowlist — показати, якщо збігається ХОЧА Б ОДИН item;
     denylist  — сховати, якщо збігається хочa б один item.
     Порожній список (items: []) = вимір вимкнено.

  ВИМІРИ (усі опційні; кожен з mode + items):
     display_name  — regex по показуваному імені
     username      — regex по логіну (завжди маленькими літерами)
     user_id       — ТОЧНИЙ збіг цифрового id (НЕ regex)
     content       — regex по тексту повідомлення (у подій тексту немає)
     message_type  — види: message | sub | gift_sub | mystery_gift |
                     raid | redeem | cheer (інше ім'я = помилка конфіга)
     role          — бейджі відправника: moderator, vip, subscriber,
                     broadcaster, founder, lead_moderator, global_mod, ...

  ПРИКЛАДИ (вставляй у filters: (...), зайве прибирай):

  ── Ховати чат-команди (усе, що починається на "!") ──
     content: Some((
         mode: allowlist,
         items: [ "^(?:[^!]|$)" ],   // все, крім рядків, що почалися з "!"
     )),

  ── ...але залишити свою команду !шіхтар (виняток!) ──
     content: Some((
         mode: allowlist,
         items: [
             "^(?:[^!]|$)",
             "(?i)^!шіхтар(?: |$)",
         ],
     )),
     // (?i) = без урахування регістру. Один виняток = один рядок.

  ── Забанити конкретних користувачів за id ──
     user_id: Some((
         mode: denylist,
         items: [ "1538701825", "123456789" ],
     )),
     // додати юзера = ще один id рядком у []

  ── Ховати спам за текстом ──
     content: Some((
         mode: denylist,
         items: [ "(?i)купити крипту", "(?i)^!реклама" ],
     )),

  ── Дозволяти тільки роль "vip" ──
     role: Some((
         mode: allowlist,
         items: [ "vip" ],
     )),

  ВИНЯТКИ (filters.overrides) — перевіряються ПЕРШИМИ, перший збіг
  вирішує остаточно:
     allow — показати навіть якщо вимір забороняє;
     deny  — сховати навіть якщо вимір дозволяє.
  Умови в правилі складаються через І (усі присутні мусять збігтися);
  відсутня умова = «будь-що». Правило без жодної умови — неактивне.

     overrides: [
         // повернути повідомлення конкретного бота з потрібним текстом
         ( action: allow, user_id: Some("1538701825"), content: Some("(?i)^!шіхтар(?: |$)") ),
         // ховати слово "реклама" у всіх
         ( action: deny,  content: Some("(?i)реклама") ),
         // ховати все від конкретного логіна
         ( action: deny,  username: Some("^spammer$") ),
     ],

  РАДИ (щоб не зламати конфіг):
     - Не додавай два однакові ключі в одному правилі (напр. два
       content:) — це помилка парсингу. Кілька патернів роби ОДНИМ
       regex через | :   "(?i)(?:малюк|реклама)".
     - Кривий regex або помилка в файлі → сервер відкине ВЕСЬ файл і
       лишить старий конфіг (звідси «додав фільтр, а повідомлення йдуть»).
       Перевір лог у консолі.

 8. КАСТОМНІ БЕЙДЖІ (приклади)
------------------------------------------------------------
  Секція badges: дозволяє давати людям/ролям СВОЇ картинки замість
  (або поряд з) нативними бейджами Twitch.

  СХЕМА:
     badges: Some((
         definitions: {
             "vip_custom": (
                 uri: "file://badges/vip.png",  // файл у папці badges\
                 priority: 1,                    // >0; менше = лівіше в рядку
                 height: 1,                      // висота в em (1 = як нативний)
                 label: Some("VIP"),             // підказка (опційно)
             ),
         },
         per_role: {
             "vip": (badges: ["vip_custom"], hide_native: true),
         },
         per_user: {
             "likh_tar": (badges: ["vip_custom"], hide_native: false),
         },
         cache_dir: None,
         refresh_interval_secs: 86400,
     )),

  ЯК ЦЕ ПРАЦЮЄ:
     - definitions — «реєстр» картинок: ключ -> (uri, priority, height, label).
       uri може бути:
            file://badges/badge.png  — файл у папці badges\ поруч з exe;
            https://…/badge.png      — посилання в інтернеті.
       priority обов'язкове і має бути > 0 (менше значення = раніше/лівіше).
     - per_role — приєднати бейдж до ролі. Ключ = id бейджа Twitch:
         broadcaster, moderator, vip, subscriber, founder, lead_moderator,
         global_mod, artist-badge, staff, admin, partner, prime, turbo …
       hide_native: true  — сховати НАТИВНИЙ бейдж ЦІЄЇ ролі, показувати
                            тільки кастомний.
       hide_native: false — кастомний додається, нативний лишається.
     - per_user — те саме для конкретної людини. Ключ = логін
       (напр. "likh_tar") або цифровий id.
       hide_native: true тут сховає ВСІ нативні бейджі цього юзера.

  ПРИКЛАД: свій VIP-бейдж замість нативного
     1) поклади картинку у папку badges\ (напр. badges\vip.png);
     2) впиши у chat.ron:

     badges: Some((
         definitions: {
             "vip_custom": ( uri: "file://badges/vip.png", priority: 1, height: 1 ),
         },
         per_role: {
             "vip": (badges: ["vip_custom"], hide_native: true),
         },
     )),

  ПРИКЛАД: особистий бейдж для друга
     badges: Some((
         definitions: {
             "crab": ( uri: "https://example.com/crab.png", priority: 1, height: 1, label: Some("краб") ),
         },
         per_user: {
             "vulkanchikbot": (badges: ["crab"], hide_native: false),
         },
     )),

  ДЕ ФАЙЛИ:
     Картинки клади в папку  badges\  (вона вже є в бандлі) і пиши
     file://badges/ім'я-файлу.png. Напр. файл badges\vip.png ->
     uri: "file://badges/vip.png". Підтримуються PNG і SVG.
     Шлях завжди ВІДНОСНИЙ кореня бандла (папки Quiver_windows).

  РАДИ:
     - Не став hide_native: true, поки файлу немає — буде попередження
       в лозі і порожнє місце замість бейджа.
     - Бейджі підхоплюються при старті та при збереженні chat.ron.

------------------------------------------------------------
 9. ЩО ЩЕ МОЖНА ПІДКРУТИТИ
------------------------------------------------------------
  Канал:                  chat.ron  ->  channel: "..."
  Розмір шрифту:          chat.ron  ->  font_size_px: 27
  Скільки повідомлень:    chat.ron  ->  max_messages: 30
  Час життя повідомлення: chat.ron  ->  message_lifetime_secs: 60
  Фільтри:                chat.ron  ->  filters: (...)     (розділ 7)
  Кастомні бейджі:        chat.ron  ->  badges: Some((...)) (розділ 8)
  Банери рідімок/бітсів:  chat.ron  ->  theme.event_layout  (розділ 6)
  Стиль (кольори, фон, ролі, рамки) — у css\custom-widget.css або
  css\likh_tar.css (розділ 6), усе перекоменковано з прикладами.

  Зміни в chat.ron, credentials.ron і CSS підхоплюються НАЖИВО —
  перезапускати сервер не потрібно. Достатньо зберегти файл.
  (Оновлення в самому джерелі OBS: чат перемальовується сам.)

 ПРИМІТКИ
------------------------------------------------------------
  * credentials.ron та oauth.json містять твої секрети Twitch. Нікому їх
    не передавай і не викладай у мережу. Решту папки поширювати можна.
  * Сервер працює лише на цьому ПК (127.0.0.1) і лише поки запущений.
  * Якщо щось не так — глянь лог: у консолі, або тимчасово запусти
    quiver-chat.exe без "hidden", щоб побачити повідомлення.
